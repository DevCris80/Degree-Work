# DM-08 — Mismo código en dos celulares sin señal (DE-03)

| Campo | Contenido |
|---|---|
| Requisitos | RF-17, RF-35 |
| Escenario | DE-03 (E-07) |
| Verificación automática relacionada | `BandejaRechazosE07Test`, `BandejaRechazosViewModelTest`, `03_reglas_de_las_tablas` (pgTAP). |
| Dispositivo | Samsung Galaxy A15 (SM-A155M) y Oppo A5 5G (CPH2735), cada uno con su usuario de la misma finca |
| Cómo se ejecuta | Manual en los dos celulares, con `adb` para cortar y devolver el internet (DNS privado roto), pulsar «Sincronizar ahora», copiar las bases y grabar. DM-07 y DM-08 se hicieron en la misma ventana sin internet. |
| Estado | Ejecutada el 2026-10-29: aprobada en lo esencial; la corrección con otro código depende de RF-19 |

## Preparación

- Los dos celulares sincronizados.
- Los dos en modo avión.
- Un código C que no tiene chapeta activa en la finca.

## Pasos

1. En el A15 registrar el animal X con el código C.
2. En el Oppo registrar el animal Y con el mismo código C.
3. Conectar el A15 y sincronizar: se acepta.
4. Conectar el Oppo y sincronizar.
5. Abrir la bandeja de rechazos del Oppo.
6. Corregir: asociar otro código al animal Y.

## Resultado esperado

- La subida del Oppo rechaza solo la chapeta duplicada; el resto se acepta.
- La bandeja muestra el motivo y el animal que ya tiene el código.
- Al corregir, el rechazo se cierra y se conserva.

## Criterio de aprobación

El servidor termina con una sola chapeta activa para C y el animal Y queda con su código corregido.

## Resultado obtenido

Sin internet en los dos celulares, cada uno registró un animal nuevo con el **mismo código de chapeta**, `DM08DUP` (A15: «Vaca Prueba A15»; Oppo: «dip oppo»). Cada celular lo aceptó, porque no veía la chapeta del otro (RN-01 solo se comprueba en local).

Al volver el internet, el A15 subió primero y el Oppo después:

- El servidor **aceptó** la chapeta `DM08DUP` del A15 y **rechazó** la del Oppo con el error `23505` (violación del índice único de la chapeta activa). El resto del lote del Oppo se aceptó: el animal «dip oppo» quedó sincronizado y la edición de Tornado llegó como *sibling* (DM-07).
- El Oppo muestra el aviso rosa «1 cambio rechazado» y «Hay cambios rechazados por revisar». La bandeja dice: «Chapeta DM08DUP de dip oppo. Este código ya está asociado a Vaca Prueba A15, desde otro celular», con las opciones «Asociar otro código» y «El código es de Vaca Prueba A15: cerrar».
- Los dos celulares terminaron con **una sola chapeta `DM08DUP`**, la de «Vaca Prueba A15», y sin cambios por subir.
- El rechazo se cerró (`fechaCorreccion` guardada) y se conserva en la base del Oppo, como pide ADR-0004. En la bandeja pasó a «No hay cambios rechazados».

**Lo que no se pudo hacer.** El paso 6 pide corregir asociando otro código al animal «dip oppo». «Asociar otro código» lleva al detalle del animal y a su edición, que dice «La chapeta no se modifica desde aquí»: asociar una chapeta a un animal existente es RF-19, pendiente (#94). El rechazo se resolvió cerrándolo, y «dip oppo» quedó sin chapeta. Por eso RF-35 sigue parcial.

Evidencia: [DM-08.mp4](DM-08.mp4) (A15 a la izquierda, Oppo a la derecha) y `scripts/resultados/dm07-08-20261029130310/`. Mismas limitaciones de grabación que DM-07.
